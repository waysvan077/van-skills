## 1. Model

There is one state directory, one database, one vault, and one browser profile per identity. The
CLI is a thin layer over the `aa` package; MCP calls the same functions. Policy is evaluated twice:
by the caller and again inside the library, so a host that bypasses the CLI cannot bypass the cap.

Three actors:

| actor | does | never does |
|---|---|---|
| operator | sets mode, approves frozen payloads, handles captcha/login | edits the DB |
| agent/host | chooses commands, reads envelopes | signs without the guard |
| library | policy, crypto, browser, proofs | trust the caller |

## 2. Install and layout

```bash
unzip airdrop-agent-v4.zip && cd airdrop-agent
./install.sh              # macOS/Linux, venv, deps, chromium
./install.sh --full       # adds Foundry
./install.sh --no-browser # CI / remote, install chromium later
./install.sh --service    # writes a systemd/launchd unit template
```

Then:

```bash
aa init
aa doctor
```

`aa init` creates `~/.airdrop-agent`, an `.env` with mode 0600 and a generated
`VAULT_PASSWORD`. Losing that password loses the keys; `aa vault export` with its own password is
the backup that survives it.

```
~/.airdrop-agent/
  .env                 secrets, 0600
  policy.yaml          chains, allowlists, caps, modes
  autopilot.yaml       module switches and intervals
  data/state.sqlite3   identities, wallets, quests, runs, gates, events
  vault/               AES-256-GCM blobs (index + secrets)
  browser/<id>/main/   the Chromium profile that keeps logins
  quests/              imported YAML
  proofs/              screenshots and run artefacts
```

`AIRDROP_HOME` moves the whole tree. `AA_BROWSERS_PATH` points at the Chromium build.

## 3. Configuration

`.env` keys that matter:

| key | meaning |
|---|---|
| `VAULT_PASSWORD` | required; generated by `aa init` |
| `RPC_<CHAIN>` | per-chain RPC override, tested by `aa doctor` |
| `AGENT_EMAIL` | fallback email for forms |
| `TELEGRAM_API_ID/HASH`, `TELEGRAM_OWNER_ID` | MTProto and the owner who receives gate codes |
| `BROWSER_HEADLESS` | `1` on servers |
| `BROWSER_PROXY` / `PROXY_<IDENTITY>` | per-identity egress |
| `CF_*` | Cloudflare behaviour, see [CLOUDFLARE](CLOUDFLARE.md) |
| `SESSION_*` | state mirror, see [SESSIONS](SESSIONS.md) |
| `CAPTCHA_PROVIDER`, `CAPTCHA_API_KEY` | `2captcha` or `anticaptcha` |

`policy.yaml` is the contract: chains, `testnet` flags, `native_decimals`, caps, domain and
contract allowlists, mode presets. `null` cap means deny. Edit it, then `aa doctor` again.

Modes:

```bash
aa mode            # show
aa mode balanced   # set
```

Never move to `turbo` for a wallet holding real money without reading [SAFETY](SAFETY.md).

## 4. Identities

```bash
aa identity new main --persona casual-id --proxy http://user:pass@host:port --wallets 2
aa identity list
aa identity show main
aa identity set main notes "X: @handle"
```

An identity is a persona, a proxy, a seed, wallets, socials, an email and a browser profile. Create
one, take it end-to-end, then clone the pattern. `aa identity clone` copies persona and proxy, not
the seed.

`--wallets N` provisions N EVM and N Solana addresses from a fresh 24-word seed in the same call.

## 5. Wallets and custody

```bash
aa wallet list --identity main
aa wallet new --identity main --count 10
aa wallet balance --identity main --chain base-sepolia
aa wallet import --identity main --chain evm --secret 0x…
aa wallet import --identity main --chain evm --mnemonic --secret "word …"
aa wallet import --identity main --chain sol --secret "[1,2,…]"
aa wallet export --identity main
aa wallet sign --identity main --label evm-1 --message "hello"
aa wallet approve --identity main --label evm-1 --token 0x… --spender 0x… --amount 100 --broadcast
```

Custody facts:

- one seed per identity, BIP44 (`m/44'/60'/0'/0/i` EVM, `m/44'/501'/i'/0'` Solana).
- vault is AES-256-GCM with scrypt and AAD; moving a blob breaks it.
- the seed never prints; `wallet export` shows addresses plus ciphertext.
- `vault export` seals the whole tree with a separate password and prints a SHA-256.

Keep farming wallets on gas only. Sweep profits.

## 6. Browser engine

```bash
aa browser --identity main --url https://app.example.com --headful
aa browser --identity main --url https://x.com --login --minutes 10
aa ext list
aa ext install rabby --identity main
```

The engine launches a persistent Chromium per identity, injects an EIP-1193 provider and a Phantom
provider backed by Python, plus a stealth shim. Extensions are downloaded from the official store
and their manifests patched for automation. Without extensions the injected providers still work.

All modules share the profile `main` by default. `BROWSER_SEPARATE_PROFILES=1` restores the old
one-profile-per-module behaviour; `BROWSER_PROFILE` names another profile.

Screenshots, snapshots and `aa quest probe` are the debugging surface. There is no hidden DOM
magic: if a selector is wrong, the step fails loudly with a screenshot.

## 7. Cloudflare

Three layers, in order:

1. **Reuse.** A solved `cf_clearance` is stored per identity + host with its user agent and injected
   before navigation, valid for `CF_TTL_MINUTES`.
2. **Solve.** Real mouse movement, scroll, focus and a Turnstile checkbox click; then a provider
   token (2captcha/anticaptcha with `action` + `cdata`); then FlareSolverr if configured.
3. **Assist.** A visible window on the same profile, one click by you, cookie captured.

```bash
aa cf status
aa cf assist --identity main --url https://app.example.com/points
aa cf clear --identity main --host app.example.com
```

`clearance` is bound to IP and UA: change proxy and it is invalid, which is why each identity keeps
one proxy. Full details: [CLOUDFLARE](CLOUDFLARE.md).

## 8. Sessions

Logins die for two reasons: a new profile per action, and no activity. The fix is structural:

- one profile per identity, reused by every module;
- `storage_state` mirrored into the vault on close and restored on start;
- `warm` scrolls real pages on the platforms already linked;
- quests pre-flight the login and park with `needs_login` instead of failing.

```bash
aa session status --identity main
aa session check --identity main --platforms x discord
aa session warm --identity main
aa session save --identity main
aa session restore --identity main
aa social login x --identity main --user … --password …
```

Autopilot warms every four hours by default. Details: [SESSIONS](SESSIONS.md).

## 10. Quests

A quest is YAML: `id`, `url`, `steps`, optional `platform`, `chain`, `daily`, `cooldown_hours`,
`gate`.

```yaml
id: example-daily
name: Example daily
url: https://app.example.com/tasks
platform: custom
chain: base-sepolia
cooldown_hours: 24
steps:
  - goto: "{{url}}"
  - dismiss: true
  - wallet: {connect: true}
  - click: "Check in"
  - manual: "solve the quiz if it opens"
  - screenshot: done
```

Templates: `{{url}}`, `{{email}}`, `{{wallet}}`, `{{solwallet}}`, `{{handle}}`, `{{twitter}}`.
Step syntax and every action: [QUESTS](QUESTS.md).

Lifecycle:

```bash
aa quest probe https://app.example.com/tasks   # what fields/buttons/challenge exist
aa quest import file.yaml
aa quest validate example-daily
aa quest run example-daily --identity main --dry
aa quest run example-daily --identity main
aa quest list --status pending
aa quest due
```

Run statuses: `done`, `parked`, `failed`, `blocked`, `dry`. `parked` is not an error; it means a
human step remains and the command prints the screenshot and the next command. A parked quest is
skipped by autopilot for six hours.

Proofs hold step outcomes, screenshots, gate ids and tx hashes. A daily quest records a check-in so
the cooldown and streak are enforced.

Pre-flight: steps touching X, Telegram or Discord call `session.ensure` first. Logged out →
`needs_login` with `aa social login …` as next, never a half-finished run.

The build was tested against the sites in [TARGETS](TARGETS.md). Nineteen quests are prebuilt:

Points: `dow-points`, `ammora-checkin`, `vapi-earn`, `qyro-manifest`, `syqora-register`,
`bullshot-gem`, `dogeos-heist`, `kiedex-login`.

Testnet: `nilly-faucet`, `stabilizer-faucet`, `flint-perps`, `whisk-swap`, `ducat-vault`,
`polyester-trade`, `tzer0-mission`, `folester-play`.

Waitlist/whitelist: `oripa-raffle`, `codekitty-whitelist`, `zkunnamed-apply`.

Run one:

```bash
aa quest import config/quests/dow-points.yaml
aa quest run dow-points --identity main
```

Most stop at a `manual` step by design: a quiz answer, a signature prompt, a deposit amount, an X
post URL. That is the honest boundary between automation and your judgement.

## 12. Testnets and sending

```bash
aa testnet status
aa testnet faucets --chain base-sepolia
aa testnet claim --chain base-sepolia --identity main
aa testnet campaign --chain base-sepolia --identity main --rounds 3
aa testnet deploy --chain sepolia --identity main --kind erc721
aa wallet send --chain sepolia --identity main --label evm-1 --to 0x… --amount 0.005
aa wallet send … --broadcast
```

Order inside a send: policy check → payload hash → optional gate → simulation → gas cap → sign →
broadcast. `to` empty means contract creation. Solana has its own command `aa wallet sol-send`.

Faucets are catalogued in `config/faucets.yaml` with cooldowns. A claim that hits an unwinnable
challenge parks with a screenshot rather than looping.

## 13. Daily and autopilot

```bash
aa daily plan --identity main
aa daily run --identity main
aa daily status --identity main
aa autopilot plan
aa autopilot tick --headful
aa autopilot daemon
```

Tick order: radar → auto-follow → warm → daily → quests → faucet. Each module has an interval,
daily budgets are counted from events, and `active_hours` silences the night. Toggle modules in
`autopilot.yaml`. `tick` is the safe unit; `daemon` is a foreground loop under systemd/launchd.

## 14. MCP and other agents

```bash
aa mcp serve
```

stdio JSON-RPC, 21 tools: status, identities, wallets, balance, send, sign, social, quests, radar, gates, session, cf,
quests, quest run, radar, daily, gate approve/list, browser snapshot, kill. Vault export, mode
switch and browser manual flows stay CLI-only because they are interactive.

Host adapters: [agents/](../agents/README.md). `AGENTS.md` is the router; `SKILL.md` is the deep
skill. Hermes and OpenClaw get a shell shim, Muse a tool manifest, Claude the MCP config.

## 15. Approvals, gates and kill

A gate freezes a canonical payload: `_kind`, chain, identity, recipient, amount, calldata, origin.
`aa gate approve <id> <CODE>` binds the hash to a one-time code delivered to the owner on Telegram.
The same command re-run consumes it; any changed field produces a different hash and a new gate.

Exit codes: `0` ok, `2` denied, `3` failure, `10` gate, `99` kill. A host must branch on them, not
on prose.

`aa kill "reason"` writes `KILL` and every entry point refuses with 99. `aa unkill` clears it.
`aa allow add domain app.example.com` and `aa allow add contract base 0x…` widen scope without
editing YAML.

## 16. Safety and sybil

Read [SAFETY](SAFETY.md) and [SYBIL](SYBIL.md). Short version: one identity per human-looking
persona, one residential proxy per identity, warm before acting, vary timing, never connect a fresh
wallet to ten protocols in one minute, keep gas-only balances, and check the scam verdict before
signing anything unfamiliar.

## 17. Operations

```bash
aa status
aa events --limit 50
aa autopilot daemon                # or templates/systemd, templates/launchd
aa vault export ~/backup.aa --password 'strong'
aa vault import ~/backup.aa --password 'strong'
```

Back up: vault export, `.env`, `policy.yaml`, `quests/`. Not the profile tree. Restore in order:
install, `aa init`, edit `.env`, `aa vault import`, `aa session restore`.

Upgrade: unzip over the old tree, `./install.sh`, `aa doctor`, `aa migrate`.

## 18. Troubleshooting

| symptom | cause | fix |
|---|---|---|
| exit 2 "VAULT_PASSWORD not set" | `.env` placeholder | `aa init` regenerates it |
| `ProcessSingleton` | stale lock | engine clears and retries; else delete `browser/<id>/main/Singleton*` |
| loop on "Just a moment" | challenge not passing | `aa cf assist`, or set a provider / FlareSolverr |
| `needs_login` | session expired | `aa social login …`, then `aa session warm` |
| faucet "field not found" | selector renamed | `aa quest probe` the faucet, patch YAML |
| RPC 429 | public endpoint | set `RPC_<CHAIN>` to your own |
| quest parks forever | manual step, parked skip | finish it, `aa quest run` |

## 19. Reference

Exit codes, envelope keys, step vocabulary ([QUESTS](QUESTS.md)), env keys ([env.example](../config/env.example)),

Shell completion: `aa --help` lists every group; each group has its own `--help`.

## 20. Limits

- Captcha without a key is manual.
- Turnstile is designed to be hard in headless; keep a provider or FlareSolverr on servers.
- Points are not tokens; a quest completing is not an allocation.
- Selectors are the fragile part. `quest probe` is the maintenance tool.
- Discord user tokens and multi-account farming are ToS-grey, not ToS-clean.
